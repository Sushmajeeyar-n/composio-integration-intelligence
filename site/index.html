02 / Research framework

What makes an integration buildable?

Authentication

OAuth 2.0, API keys, tokens, Basic auth or other methods. What credentials does an agent need?

Access model

Can a developer self-serve credentials, or are paid plans, admin approval or sales contact required?

API surface

Is there a documented REST or GraphQL API? What breadth of operations is available?

MCP support

Does an official or community MCP server exist? What tools and capabilities does it expose?

Final buildability assessment

Each app should receive a verdict supported by its evidence: integration readiness, access constraints, API coverage, MCP availability and the main implementation blocker.

03 / Research workflow

A repeatable evidence pipeline

STEP 01

Discover

Read the 100-app input list and search official developer, API, authentication and MCP documentation.

STEP 02

Prioritize

Score candidate results using documentation-related keywords and domain signals. Keep original evidence for comparison.

STEP 03

Verify

Compare source identity and relevance against documentation. A human must confirm the facts before they enter the final research table.

Implementation: Python, CSV, DuckDuckGo search (DDGS), URL-domain parsing and a human review log.

05 / Verified example

Salesforce: a deeper evidence-backed case

Salesforce is the only app with a completed detailed research record at this stage. Its findings illustrate why authentication, permissions, API access and MCP availability must be considered together.

Authentication

OAuth 2.0 is used to authorize client applications accessing REST API resources.

Salesforce OAuth and Connected Apps documentation ↗

API access constraints

API access is enabled by default in Enterprise, Performance, Unlimited and Developer Edition orgs. Professional Edition requires an API add-on. Users also need the API Enabled permission.

Salesforce supported editions and permissions ↗

Hosted MCP

Salesforce provides standard hosted MCP servers. They are disabled by default and require administrator activation. Tool calls respect Salesforce permissions and sharing controls.

Salesforce standard MCP server reference ↗

SObject All

The documented server includes tools for schema discovery, SOQL queries, searching, record creation, updates, deletion and related-record operations.

SObject All tool reference ↗

Strong candidate

Main blockers: edition/API access restrictions, OAuth setup, user permissions and administrator activation of hosted MCP servers.

06 / Limitations and next work

What remains to be established

  • Complete structured research for the remaining 99 apps.
  • Verify credential availability and paid-plan requirements from current official documentation.
  • Confirm API breadth and distinguish official MCP servers from community implementations.
  • Expand the human-reviewed sample across categories and compare the second-pass ranking against the first.
  • Calculate category-level patterns and evidence-backed buildability recommendations.

No unsupported access claims or buildability verdicts are inferred from search snippets alone. Missing evidence is a research gap, not proof that an integration is impossible.
